# 모바일 검증

## 1. 자동 검사 (순서대로, 실패 시 멈추고 원인 보고)
```
npm run typecheck
npm run test
npm run build
```
- `package.json`에 스크립트가 없으면 CLAUDE.md "명령어" 절의 정의대로 추가하자고 먼저 알리고, 임의로 다른 명령을 만들지 않는다.
- 빌드 후 `dist/` 용량을 확인한다 (JS gzip 기준 100KB 이하 목표).

## 2. 화면 확인 (가능한 경우)
- `npm run dev -- --host` 로 띄우고 사용자에게 휴대폰에서 접속할 주소를 알려준다.
- 브라우저 도구(built-in browser / Chrome)가 있으면 뷰포트 **375×812**, **360×640** 두 크기로 홈 → 게임 설정 → 입찰 → 결과 → 최종 화면 스크린샷을 확인한다.
- 브라우저 도구가 없으면 코드 기반 점검(3번)만 하고 "실기기 확인 필요"라고 명시한다.

## 3. 모바일 체크리스트 (변경된 화면 대상)
- [ ] 가로 스크롤 없음 (고정 폭 요소, 긴 단어, `min-width` 확인)
- [ ] 터치 타깃 ≥ 44×44px, 인접 버튼 간격 ≥ 8px
- [ ] 주요 액션이 하단 고정 바에 있고 `env(safe-area-inset-bottom)` 반영
- [ ] 높이는 `100dvh` 사용, 키보드가 올라올 때 입력창 가려지지 않음
- [ ] hover 전용 정보 없음, `touch-action: manipulation` 적용
- [ ] 폰트 16px 이상인 입력창 (iOS 자동 확대 방지)
- [ ] 핫시트 모드: 제출 사이에 가림(handoff) 화면이 있어 이전 사람 선택이 노출되지 않음
- [ ] 새로고침해도 진행 중 게임이 `localStorage`에서 복구됨
- [ ] 사용자 입력이 이스케이프되어 렌더링됨

## 4. 보고 형식
- 자동 검사 결과(통과/실패 + 실패 출력 요약)
- 체크리스트 중 위반 항목만 `파일:줄` 과 함께 나열
- 실제로 확인하지 못한 항목은 "미확인"으로 구분
