# 유세 대작전 규칙 명세

기준 구현: `docs/election-mancala-standalone.html` 의 `<script>` (49~119행 부근). 이 문서와 프로토타입이 다르면 **프로토타입이 정답**이고 이 문서를 고친다.

## 구성

| 인덱스 | 라벨 | 이름 | 선거인단(용량) |
|---|---|---|---|
| 0 | A | 수도권 | 8 |
| 1 | B | 동해안권 | 7 |
| 2 | C | 서해안권 | 6 |
| 3 | D | 중원권 | 6 |
| 4 | E | 산악권 | 4 |
| 5 | F | 도서권 | 4 |

- 권역은 원형으로 A→B→C→D→E→F→A 시계 방향.
- 권역의 토큰은 **쌓인 순서가 있는 배열**. `hole[0]`이 맨 아래(가장 먼저 놓인) 토큰 = ⚑ 깃발.
- 포화(full): `hole.length >= CAP[i]`.
- 플레이어 0 = 🔵 파랑(선공), 1 = 🔴 빨강.

## 초기 상태

- 예비군 `reserves = [10, 11]`, 셋업 토큰 `setupLeft = [4, 4]`, 현재 플레이어 0, 단계 `setup`, 보드 비어 있음.

## 단계(phase)

`setup → (place → pick → sow)* → over`

### setup
- 현재 플레이어가 포화되지 않은 권역 하나에 토큰 1개를 놓는다(셋업 토큰에서 차감, 예비군 아님).
- 놓을 때마다 플레이어 교대. 양쪽 셋업 토큰이 모두 0이 되면 플레이어 0으로, 단계는 `canPlace ? place : pick`.

### place (① 예비군 투입)
- `canPlace(p) = reserves[p] > 0 && 포화 아닌 권역이 존재`.
- 턴 시작 시 `canPlace`가 거짓이면 place를 건너뛰고 바로 pick.
- 예비군 1개를 포화 아닌 권역에 놓는다. 같은 권역에 두 번 놓아도 된다.
- 1개 놓은 뒤: 여전히 `canPlace`면 place 유지(두 번째 투입 또는 `endPlace` 선택 가능). 아니면 pick.
- 2개 놓으면 pick. **최소 1개는 놓아야** `endPlace` 가능.

### pick (② 출발지 선택)
- 토큰이 1개 이상 있는 아무 권역(색 무관, 상대 토큰만 있어도 됨)을 고른다.
- 그 권역의 토큰 전부를 버스에 태우고 권역은 빈다. 버스 위치 포인터 = 그 권역.

### sow (③ 유세 순회)
- 다음 정차지 `next = 포인터 다음 칸부터 시계 방향으로 6칸(출발 권역 자신 포함, 지금은 비어 있음)을 보며 처음 만나는 포화 아닌 권역`.
- 버스에 두 색이 섞여 있으면 플레이어가 하차할 색을 고른다. 한 색만 남았으면 자동으로 하차.
- 하차: 토큰 1개를 `next`에 push, 포인터 = `next`.
- `next`가 없으면(모든 권역 포화) 남은 버스 토큰은 전부 소멸(낙선). 하차 직후에도 같은 검사를 한다.
- 버스가 비면 턴 종료.

### 턴 종료 (`fin`)
- `포화 권역 수 >= 4` 또는 `reserves[0] + reserves[1] == 0` → `over`.
- 아니면 투입 카운트 0으로, 플레이어 교대, 단계 `canPlace ? place : pick`.
- 종료 검사는 **턴 종료 시점에만** 한다(투입·하차 도중 포화 4곳이 되어도 턴은 끝까지 진행).

## 점수와 승패

- 권역별: 빈 권역은 아무도 못 얻음. 파랑 수 > 빨강 수면 파랑, 반대면 빨강, 같으면 `hole[0]`(⚑)의 색이 `CAP[i]`를 얻는다.
- 승자: 총점 큰 쪽 → 같으면 남은 예비군 많은 쪽 → 같으면 무승부.

## 구현 시 주의할 엣지 케이스

- pick 단계에서 비어 있지 않은 권역이 없는 경우: 프로토타입은 처리하지 않는다. 구현에서는 방어적으로 턴 종료 처리하고 테스트로 고정한다(도달 가능성도 테스트로 확인).
- 상대 차례에 상대가 예비군 0개이면 place를 건너뛴다(게임은 양쪽 합이 0일 때만 끝남).
- 깃발(⚑)은 권역이 비워졌다가 다시 채워지면 새 첫 토큰으로 바뀐다.
- 셋업 중 포화는 사실상 발생하지 않지만(최대 8개) 검사 로직은 동일하게 둔다.

## 프로토타입 AI (패리티 기준)

- 평가 `ev(s, m)`: 종료 상태면 승 +1000 / 무 0 / 패 -1000. 아니면 `(내 점수 - 상대 점수) * 3 + 0.3 * Σ_권역(2 * 내 토큰 수 - 전체 토큰 수)`.
- 셋업: 놓을 수 있는 권역마다 `ev + random()` 최대인 곳.
- 본 턴(`aiPlan`): 내 모든 수(투입 조합: 1개 `[i]` 또는 2개 `[i, j], j >= i` × 출발지 × 하차 순서는 매 갈림길에서 1수 앞 `ev` 탐욕 선택)를 펼치고, 각 결과에 대해 상대의 빠른 응수(투입 1개만, 하차는 자기 색 우선)의 최소 `ev`를 값으로 삼는다. `+ random() * 0.3` 노이즈. 최대값 선택.
- 연출 타이밍: AI 생각 600ms, AI 투입 간 900ms, 하차 간 800ms. (core가 아니라 game 계층 상수)

## 프로토타입 함수 대응표

| 프로토타입 | 의미 |
|---|---|
| `S` | 현재 게임 상태 |
| `s.h` / `s.r` / `s.su` | 권역 배열 / 예비군 / 셋업 남은 토큰 |
| `s.p` / `s.ph` / `s.pc` | 현재 플레이어 / 단계 / 이번 턴 투입 수 |
| `s.bus` / `s.ptr` / `s.src` | 버스 토큰 / 버스 위치 / 출발 권역 |
| `s.n` | 온라인 동기화용 버전 카운터 |
| `s.hl` | UI 하이라이트(마지막 하차 권역) — core에 넣지 말 것 |
| `put` / `pick` / `drop` / `step` / `fin` | setup·place 처리 / 출발 / 하차 / 단색 자동하차 / 턴 종료 |
| `nxt` / `full` / `score` / `winner` / `canPlace` | 다음 정차지 / 포화 수 / 점수 / 승자 / 투입 가능 |
| `cl` / `ev` / `moves` / `aiPlan` | 상태 복제 / 평가 / 수 생성 / AI 계획 |
