# 규칙 조항 구현 절차

## 0. 범위 정하기
- 구현할 조항을 `docs/rule.md`에서 찾아 절 번호(예: §8 쌓기 규칙)와 문장을 그대로 인용해 정리합니다.
- 모호하거나 빠진 부분이 있으면 **구현 전에** 사용자에게 묻습니다. 기본값을 정해 진행해도 되는 사소한 것이면 그 결정을 보고에 명시합니다.
- 사용자가 결정한 내용은 동의를 받아 `docs/rule.md`에 반영합니다. (규칙서 변경은 별도 커밋 `규칙: …`)

## 1. 테스트 먼저
- `engine-tester` 서브에이전트에 조항과 기대 동작을 넘겨 실패하는 테스트를 작성하게 합니다. 간단하면 직접 작성해도 됩니다.
- 규칙서의 예시(> 예: …)는 모두 테스트로 옮깁니다.

## 2. 구현
- `src/engine/` 안에서만 구현합니다. CLAUDE.md의 아키텍처 원칙(순수 리듀서, 시드 RNG, JSON 상태, 주사위 계산은 dice.ts)을 지킵니다.
- 카드는 데이터 + 판정 함수로 추가합니다. 우주 법칙처럼 기본 규칙을 바꾸는 효과는 규칙 함수에 매개변수/훅으로 주입하고, 규칙 코드 곳곳에 `if (law === …)`를 흩뿌리지 않습니다.
- `npm test`와 `npm run typecheck`를 통과시킵니다.

## 3. 감사
- `rules-auditor` 서브에이전트로 해당 조항을 검증합니다.
- 불일치는 고치고, "규칙서가 모호한 부분"은 사용자에게 전달합니다.

## 4. 커밋
- `/commit-push` 스킬로 커밋 & 푸시합니다. 메시지에 관련 조항을 적습니다.
  예: `기능: 4라운드 시간 세기와 돌리기 구현` / `- 관련 규칙: docs/rule.md §9`
