# 룰북 작성 규칙

## 문장 규칙
1. **한 문장에 한 규칙.** "~하고, ~하면 ~한다"처럼 여러 규칙을 잇지 않는다.
2. **주어를 생략하지 않는다.** "이동한다" 대신 "로봇은 앞으로 1칸 이동한다", "조종사는 개입 하나를 할 수 있다".
3. **용어는 `docs/glossary.md`와 정확히 일치시킨다.** 처음 등장할 때 **굵게** 표시한다. 용어집에 없는 용어가 필요하면 먼저 용어집에 추가한다.
4. **모호한 표현을 쓰지 않는다.** "근처", "약간", "적당히", "가능하면" 대신 칸 수, 개수, 조건을 쓴다.
5. **시점을 명시한다.** "라운드 시작 시", "실행 단계 종료 후"처럼 언제 일어나는지 쓴다.
6. **"할 수 있다"(선택)와 "한다"(의무)를 구분한다.**
7. **예외는 원칙 바로 아래에 둔다.** 다른 섹션에 흩어 놓지 않는다.
8. **조종사와 설계자를 구분해 쓴다.** "플레이어"라고 쓰면 누구를 말하는지 헷갈리는 문장에서는 반드시 조종사·설계자로 쓴다.

## 타일 문구 규칙
규칙 타일은 실행 중 빠르게, 누구나 같은 결과로 판정해야 한다(디자인 기둥 3).
1. **형식은 `조건 → 행동` 한 줄이다.** 조건이 없는 타일은 `항상 → 행동`으로 쓴다.
2. **조건은 보드에서 바로 셀 수 있는 것만 쓴다.** 거리(칸 수), 방향(앞·뒤·좌·우), 개수, 인접 여부.
3. **거리와 인접의 기준은 룰북 한 곳에서 정의하고, 타일은 그 정의를 따른다.** 타일마다 기준을 따로 두지 않는다.
4. **행동이 불가능할 때의 처리는 룰북의 일반 규칙으로 정한다.** 타일에 예외를 적지 않는다.
5. **아이콘과 문장이 함께 있으면 둘의 의미가 정확히 같아야 한다.**

## 구조 규칙
- 섹션 순서: 개요 → 구성물 → 준비 → 라운드 진행 → 세부 규칙 → 게임 종료 → 예외/FAQ
- 라운드 진행은 번호 매긴 단계로 쓴다.
- 복잡한 규칙 뒤에는 `> 예시:` 블록으로 구체적인 상황을 하나 보여준다.
- 이 게임 특유의 혼동 지점(슬롯 우선순위, 여러 로봇의 실행 순서, 개입 시점)은 예시를 반드시 붙인다.

## 수정 후 할 일
1. 규칙이 바뀌었으면 `/design-log`로 결정을 기록한다.
2. 상단 버전 표기(`초안 vX.Y`)를 올린다. 큰 구조 변경은 X, 문장 수정은 Y.
3. 구성물이나 규칙 타일 목록이 바뀌었으면 `components/components.md`를 갱신한다.
4. 큰 변경이면 `rules-reviewer` 에이전트로 검수를 제안한다.
