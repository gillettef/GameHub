## 검토 대상

`client/src/**`. 범위가 없으면 최근 변경 파일(`git diff HEAD~1 --name-only`)을 우선 본다.

## 전제 (notes/구현방법, notes/Rules.md, F008~F015)

- 탭 전환은 100ms 이내. 탭 컴포넌트는 언마운트하지 않고 `display:none`/`visibility` 로 숨긴다.
- 표준 데스크톱 해상도(1366×768 이상)에서 수직 스크롤 없이 15×15 보드·손패·패스 버튼이 모두 보여야 한다.
- 전역 상태(Zustand)에 모든 탭 데이터를 선로드한다. 클라이언트는 게임 규칙을 계산하지 않는다. 배치 가능 칸 등 UI용 계산은 `shared/src/engine` 함수를 그대로 쓴다.
- 정원 탭: 드래프트 중에는 드래프트 화면(목표 3장·식물 12종 카드·고른 종), 진행 중에는 목표 칩 + 육각 SVG 보드(지형·땅 주인 자리 색·식물·입구·씨앗·합법 칸·미리보기) + 손패(최대 3장) + 심기 확인 바(칡 방향·민들레 씨앗) + 차례 안내. 점수 탭: 자리별 땅·목표·무궁화·덤·합계, 목표별 점수. 진행 탭: 로그. 카드 탭: 종·목표 카탈로그. 설명 탭: 규칙 요약.

## 검토 항목

1. **탭 마운트 전략**: 탭 전환 시 조건부 렌더링(`{tab === 'board' && ...}`)으로 언마운트하는 곳이 있는가.
2. **리렌더 범위**: `React.memo` 미적용 탭 컴포넌트, 스토어 전체를 구독하는 `useStore()` 호출(선택자 없음), 매 렌더마다 새로 만드는 콜백·객체 prop.
3. **보드 (F008, F009)**: 최대 105칸(4인). buildCells(영향력·땅 계산)가 상태가 바뀔 때만 다시 계산되는지(useMemo). 카드 선택 → 합법 칸 하이라이트 → 칸 탭 → 미리보기 → 심기 확정 흐름에서 이중 전송 방지(sending). 내 차례 아닐 때 선택 차단. 씨앗 고르기 모드 전환.
4. **레이아웃 (F015)**: `100vh` 기반 고정 레이아웃인가. 진행 탭 로그처럼 내부 스크롤이 필요한 영역만 `overflow:auto` 인가. 1366×768, 1920×1080에서 보드 + 손패가 함께 들어가는가. 보드 크기(11/13/15)에 따라 셀 크기가 뷰포트에 맞춰 조정되는가.
5. **점수 탭 (F010, F011)**: 점수 분해(땅·목표·무궁화·덤)가 엔진 computeScores 결과와 같은지, 기권자 표시.
6. **턴 제어 (F013)**: 남의 턴에 패스·기권 비활성화, 연타 방지, 기권 확인 단계.
7. **소켓 → 스토어**: 서버 브로드캐스트를 받아 스토어를 통째로 교체할 때 참조 동일성이 깨져 모든 탭이 리렌더되는지. 필요하면 슬라이스별 갱신 제안.
8. **접근성·가독성**: 탭 키보드 접근, 툴팁(F008)의 포커스 처리, 셀 좌표 읽기.
9. **DESIGN.md 준수** (CLAUDE.md "디자인 규칙"): `box-shadow` 사용, 각진 CTA, 컴포넌트 CSS에 HEX 직접 기입, `tokens.css` 외 색 정의, 비게임/게임 두 세계의 색 혼용, 헤딩에 순수 검정 사용을 지적한다. 미정 색(자리 1~3, 경고색)에 임의 값이 들어갔는지 확인한다. 상태 문구가 "오류" 대신 다음 할 일을 적는지("내 뿌리가 닿는 빈 칸에만 심을 수 있습니다").
