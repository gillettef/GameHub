# /mobile-check — 모바일 검증

## 1. 자동 검사 (순서대로, 실패하면 멈추고 원인 보고)
```
npm run typecheck
npm test
npm run build
npm run e2e
```
- `npm run e2e` 는 빌드 결과를 허브(/neoterra/)로 띄워 iPhone 17 Pro 화면으로 모드를 끝까지 두고 `shots/` 에 캡처한다. 캡처를 직접 연다. 린트는 GameHub 루트에서 `npm run lint`.
- 빌드 후 `dist/` JS gzip 크기를 보고한다(목표 150KB 이하).

## 2. 화면 확인
- `shots/` 캡처(처음 화면 → 대국 → 메뉴 → 결과 → 돌려 하기 → 온라인 대기실·복귀·관전)를 본다. 안전 영역은 데스크톱 WebKit 에서 0 이므로 실기기 확인이 따로 필요하다.

## 3. 체크리스트 (변경된 화면 대상)
- [ ] 가로 스크롤 없음(고정 폭, 긴 단어, `min-width`)
- [ ] 터치 타깃 ≥ 44×44px, 인접 버튼 간격 ≥ 8px
- [ ] 공통 `GameShell` ①~⑤ 배치, 페이지 세로 스크롤 없음(③ 영역 안에서만), 주요 행동이 ⑤ 하단
- [ ] hover 전용 정보 없음, `touch-action: manipulation`
- [ ] 테크 웹: 360px 폭에서 노드 구분 가능, 상태(연구됨/가능/불가)가 색 외에 모양·아이콘으로도 구분, 노드 탭 → 상세 시트
- [ ] 퀘스트 트랙: 5칸 줄바꿈(가로 스크롤 아님), 뒷면·시야 칸 구분
- [ ] 남은 지휘/방위 행동 수 항상 표시, 불가 행동은 이유 문구
- [ ] 색·간격 값이 `tokens.css` 변수로만
- [ ] 비공개 정보: 시야 밖 미래 퀘스트·덱 순서 노출 없음
- [ ] 새로고침 시 진행 중 게임 `localStorage` 복구
- [ ] 사용자 입력은 `textContent`

## 4. 보고
- 자동 검사 결과(통과/실패 + 실패 출력 요약)
- 위반 항목만 `파일:줄` 과 함께
- 확인 못 한 항목은 "미확인"
- 깊은 UX 검토는 `mobile-ui-reviewer` 에이전트에 맡긴다.
