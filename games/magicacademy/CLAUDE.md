# CLAUDE.md

이 문서는 이 저장소에서 작업하는 모든 AI 코딩 에이전트(Claude Code 등)가 반드시 따라야 할 규칙을 정의합니다.

## 프로젝트 개요

**마법학교**는 신비롭고 아기자기한 마법 학교를 배경으로 한 보드게임을 웹 서비스로 만드는 개인 프로젝트입니다.

- 원작 보드게임 기획은 `notes/` 디렉터리에 있습니다 (`마법학교_설명서.pdf`, `마법학교.pptx`, `마법학교.xlsx`). 세 자료에 서로 다른 버전의 규칙이 섞여 있으므로, **`notes/기획_정리.md`(세 자료를 검토·통합한 요약, 어느 버전이 채택되었는지와 미정 항목 정리)를 먼저 확인**한 뒤 필요 시 원본 자료를 대조합니다. 아직 세부 규칙이 확정되지 않은 부분("작성 중")이 있으므로 규칙 관련 작업 전에는 항상 최신 내용을 먼저 확인합니다.
- 지향하는 톤앤매너: **아기자기하고 귀여운(cute, cozy) 비주얼**. 어둡거나 딱딱한 판타지 톤이 아니라 밝고 사랑스러운 일러스트 감성을 목표로 합니다.
- 플랫폼: **웹 서비스**, **모바일 환경 최우선 최적화**(모바일 퍼스트: 터치 조작, 세로 화면, 작은 화면에서의 가독성/조작성을 최우선으로 설계하고, 데스크탑은 그다음으로 대응).
- 게임 핵심 개념(2026-10-17 기준 요약, 변경될 수 있음 — 현재 규칙은 `notes/기획_정리.md` 61절 "라이트 규칙" + 62절 "활동 카드 한 덱·시험 공고"(62-7 인원만큼 공개·공짜 주사위 없음)): 핵심 한 줄은 **"기운(컨디션)은 얼마든지 모을 수 있지만, 한 번에 쓸 수 있는 건 실력(능력치) + 1만큼"**. 플레이어는 학생이 되어 지력/체력/매력/주문력(시작 1)을 키우고 승점인 **학점**을 모으며 12개월 동안 1주차(학교 소식: 행사 카드 12장 중 1장 — 4월은 중간고사·10월은 기말고사 공고가 그달 소식, 그달 활동 카드 인원만큼 공개)-2주차(정규수업: 인원만큼 공개된 수업카드 중 1장, 그 과목 기운 +2, 7개월부터 주문력 과목이 많은 2학기 덱)-3주차(자율활동)-4주차(정리, 선이 시계방향 한 칸)를 진행한다. 차례는 정규수업·자율활동·시험 모두 **학점이 낮은 사람부터**(같으면 선부터 시계방향). 자율활동은 구역 없이 **활동 카드 한 덱**(마법생물 21·연구 16·탐험 16·겨루기 14장을 섞음)에서 매달 인원만큼 공개해 1장씩 고른다. 종류 = 능력치: 마법생물 조련(매력기운)·별빛 다락방 탐험(체력기운)·연구실 실험(지력기운)·마법 겨루기(마나기운). 모두 먼저 고른 뒤 고른 순서대로 진행한다. 굴릴 때는 그 카드의 기운을 **1~능력치+1개** 내고 **낸 개수만큼** 굴린다(공짜 주사위 없음, 그 기운이 하나도 없으면 주사위 1개, 다시 굴리기 없음, 결과는 확인 버튼 뒤 적용). 조련·탐험·연구는 카드의 목표 이상이면 성공하고 카드 보상을 받는다. 실패하면(겨루기는 도전자가 지면) 카드를 버리고 **낸 기운 중 1개는 남아** 다음 달로 이월된다. 성공(겨루기는 승리)하면 그 활동의 능력치 **+1(성장)·학점 +1** — 능력치는 성장·카드 보상으로만 오른다. 마법생물 카드는 학점 +1과 교감(하늘 주문력·육지 체력·바다 지력 +1), 연구 카드는 지력 이외 능력치를 준다. 마법 겨루기 카드를 고르면 친구 한 명을 지목(한 사람은 한 달에 한 번만 지목받고, 지목당해도 자기 활동은 그대로 함)해 지목당한 친구는 **주사위 1개 + 주문력**으로 자동으로 막고, 도전자가 마나기운 주사위로 **더 높아야** 승리(주문력 +1·학점 +1 + 승리 학점 +1, 그리고 "겨루며 배운다": 상대가 나보다 높은 능력치 중 차이가 가장 큰 것 +1), 막아 내도 보상은 없다. 6·12개월은 시험 달(수업·활동 없이 이월된 기운으로): 과목은 시험 카드 8장 중 무작위(중간·기말은 주사위 기운이 다름, 4·10월 공고, 예: 비행 실기 = 체력기운 주사위 + 주문력), 기운 0~능력치+1개 + 공짜 주사위 1개, 벼락치기 없음, 학점 3/2/1. 졸업식은 **네 능력치 순위**(마법상·수석상·튼튼상·생물사랑상=매력)마다 1위 +4·2위 +2·3위 +1, 시작할 때 무작위로 받는 비밀 **장래희망**(1장, 63절)의 두 능력치가 모두 5 이상이면 학점 +2. 최종 학점이 높은 사람이 이기고 같으면 1위 상이 많은 사람. 카드는 8종 151장(수업 52·마법생물 21·연구 16(목표 5~7)·탐험 16·겨루기 14·시험 8·장래희망 12·행사 12). 나중에 오프라인 보드게임으로 만들 예정이라 **동시 진행은 없다**(여러 명이 굴리는 판정도 한 명씩 차례대로). 밸런스는 전략 AI 10종(구역 성향 5종 + 판단 방식 4종 + 균형형) 리그로 검증한다(`npm run league`, 61-1절). 예전 규칙(구역·5구역·반짝 마법 경연·고정 시험·심화 수업·벼락치기·특별상·다시 굴리기 등)은 `config.ts` 스위치로 남아 있다.

## 필수 작업 규칙

1. **모든 작업 후에는 반드시 git commit & push를 진행한다.** 코드/문서 변경이 끝나면 작업을 마치기 전에 항상 커밋하고 원격 저장소로 push까지 완료한다. (이 규칙은 커밋·푸시에 대한 사전 승인으로 간주한다 — 매번 별도로 허락을 구할 필요는 없으나, 변경 내용이 크거나 위험한 작업(force push, 히스토리 변경 등)은 예외로 사용자에게 먼저 확인한다.)
2. **커밋 메시지는 가급적 한국어로 작성한다.**
3. **GitHub repo:** https://github.com/gillettef/MagicAcademy.git (기본 브랜치: `dev`). **일상 작업은 `dev`(기본 브랜치)에 커밋·푸시한다. `main`(운영 배포)에는 직접 커밋·푸시하지 않고**, 사용자가 요청할 때만 `dev` → `main` PR(`gh pr create --base main --head dev`)로 병합한다. 작업 시작 전 현재 브랜치가 `dev`인지 확인한다. `dev` 푸시는 CI(`.github/workflows/ci.yml`)만 돌고, `main` 병합이 곧 운영 배포다.
4. **터미널/채팅 세션에서 사용자에게 보내는 응답은 항상 한국어로 작성한다.** (코드, 커밋 메시지, 식별자 등은 예외로 영어를 사용할 수 있다.)
5. **세션 대화는 가급적 한국어로 실시한다.** (작업 중 진행 상황 안내도 포함)

## 기술 스택

새로운 기술 스택/라이브러리를 도입하기 전에는 사용자와 먼저 상의합니다. (2026-09-28 확정)

- **플레이 방식**: 각자 스마트폰/기기로 온라인 실시간 접속하는 멀티플레이 (한 기기 핫시트 방식 아님)
- **프론트엔드**: React + TypeScript + Vite + Tailwind CSS. 별도 백엔드 API 없이 전부 WebSocket으로 통신하므로 Next.js 같은 서버 프레임워크는 불필요, 정적 파일로 빌드
- **실시간 통신/게임 상태**: Node.js + Express + `ws`(WebSocket). 게임방(room) 상태는 서버 프로세스 메모리에만 보관 — **DB 없음**, 서버 재시작 시 진행 중인 게임은 사라짐. 단, 모바일에서 다른 앱(카톡 등)을 보고 오면 WebSocket이 끊기므로 **같은 방·같은 자리로 자동 재접속**은 지원한다 (나가기 버튼(`leave_room`)은 자발적 퇴장으로, 게임 중이면 즉시 봇이 이어받고 복귀 불가·방장은 남은 사람에게 이양. 클라이언트가 방 코드·playerId·재접속 토큰을 localStorage에 저장 → `rejoin_room`. playerId는 모두에게 공개되는 값이라 복귀에는 서버가 본인에게만 주는 비밀 `token`(room_created·room_joined)이 맞아야 한다. **게임 중 접속이 끊겨도 자리는 무기한 유지되고 봇이 대신하지 않으며 게임은 그 사람의 차례를 기다린다**(`presence`로 끊김을 모두에게 표시, 방장이 끊기면 30초 뒤 접속 중인 사람에게 이양, 전원이 30분 넘게 끊기면 방 삭제). 방장은 게임 중에도 누구든 내보낼 수 있고(`kick_player`, 2명 이상 남아야 함) 내보낸 사람은 게임에서 완전히 제거되며 `rejoin_room`도 거부됨. 대기실·끝난 게임에서 끊긴 사람만 45초 뒤 방에서 빠짐. ping/pong 하트비트로 죽은 연결 감지, 상세는 `notes/기획_정리.md` 37절)
- **계정/로그인**: 없음. 호스트가 방을 만들면 방 코드가 발급되고 다른 플레이어는 코드로 입장(Jackbox 방식)
- **운영(2026-11-24~)**: GameHub 허브 안에서 실행된다(`hub/games.json` `"mode": "inproc"`, 진입점 `scripts/aws/hub-entry.mjs` → `server/dist/app.js`의 `app`·`upgrade`·`close`). 접속은 `http://54.116.67.196/magicacademy/`. 배포하면 `deploy-remote.sh`가 `server` 런타임 의존성을 설치하고 예전 systemd `magicacademy` 서비스를 끈 뒤 허브(`gamehub`)를 재시작한다 — 허브 안 다른 게임의 진행 중인 방도 함께 사라진다. 아래 배포 설명의 포트·systemd는 예전 단독 운영 기준이다.
- **배포**: AWS EC2 t4g.nano 1대(Eleven·AstralTab과 공유, 포트 8080, systemd `magicacademy`)에서 Express 서버가 프론트 빌드 결과(정적 파일)와 WebSocket을 함께 서빙
- **자동 배포**: `main`에 병합되면 `.github/workflows/deploy-aws.yml`이 `server`의 `npm run check`(규칙 검증)를 통과했을 때만 빌드해 서버(`~/magicacademy`)에 올리고 재시작한다. SSH(22)는 관리자 IP로만 열려 있어 워크플로가 러너 IP를 임시로 열었다 닫는다. 필요한 시크릿: AWS_ACCESS_KEY_ID / AWS_SECRET_ACCESS_KEY / AWS_REGION / AWS_SECURITY_GROUP_ID / EC2_HOST / EC2_HOST_KEY / EC2_SSH_PRIVATE_KEY. 서버 설정 스크립트는 `scripts/aws/`(`provision.sh` → `units.sh`, 인스턴스 최초 1회). 게임 상태가 메모리뿐이라 재시작하면 진행 중인 판은 사라진다.
- **HTTPS/WSS**: 사용하지 않음, 순수 HTTP+WS로 단순화. 친구들끼리만 사용하는 캐주얼한 개인 프로젝트라 트래픽 암호화나 인증서 관리 부담을 감수할 필요가 없다고 판단(브라우저에 "안전하지 않음" 표시는 뜨지만 차단되지는 않음). 이후 더 넓은 공개 배포나 PWA 기능이 필요해지면 재검토
