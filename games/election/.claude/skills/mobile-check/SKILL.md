# 모바일 확인

## 1. 실행
- 기본 확인은 `npm run build && npm run e2e`(`e2e/mobile.mjs`): iPhone 17 Pro 크기 WebKit 으로 모든 모드를 끝까지 두며 `shots/` 에 캡처하고, 가로·페이지 스크롤·44pt 미만 대상·16px 미만 입력을 검사한다. 캡처는 직접 열어 본다.
- 손으로 볼 때는 `npm run dev` 로 개발 서버를 띄운다(백그라운드). 출력된 로컬 URL을 사용.
- 실제 폰 확인이 필요하면 같은 Wi-Fi에서 Network URL을 열도록 사용자에게 안내.

## 2. 뷰포트별 확인
브라우저 도구(Claude in Chrome 등)가 있으면 아래 크기로 스크린샷을 찍어 직접 본다. 없으면 사용자에게 DevTools 디바이스 모드로 확인을 요청한다.

| 기기 | 크기 |
|---|---|
| 소형 Android | 360×740 |
| iPhone 표준 | 390×844 |
| iPhone 17 Pro (기준) | 402×874 |

각 크기에서 라이트·다크 모드 둘 다.

## 3. 체크리스트
- [ ] 가로 스크롤 없음. 6개 권역과 점수판, 상태 메시지가 한 화면(스크롤 최소)에 보임
- [ ] 권역·버튼 터치 타깃 ≥ 44×44px, 인접 타깃 간 오터치 위험 없음
- [ ] 권역 안 토큰 슬롯(최대 8개)이 360px에서도 잘리지 않음
- [ ] 노치/홈 인디케이터 영역에 UI가 가려지지 않음(safe-area)
- [ ] 더블탭 확대, 길게 누르기 텍스트 선택이 게임 조작을 방해하지 않음
- [ ] 현재 차례, 선택 가능 권역, 다음 정차지가 색 외 단서로도 구분됨
- [ ] 자동 하차·AI 진행 중 입력이 막히고, 그 상태가 화면에 표시됨
- [ ] `prefers-reduced-motion`에서 애니메이션 축소
- [ ] 다크 모드에서 대비 충분 (본문 4.5:1 이상)
- [ ] 콘솔 에러 없음

## 4. 보고
문제는 "뷰포트 / 모드 / 증상 / 원인 추정 파일:행" 형식으로 정리한다. 고친 뒤 같은 뷰포트로 다시 확인한다.
