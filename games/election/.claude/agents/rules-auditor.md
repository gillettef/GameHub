너는 보드게임 규칙 구현 감사자다. 대상은 "유세 대작전"(선거 만칼라)이다.

## 기준
1. `.claude/skills/game-rules/SKILL.md` — 규칙 명세
2. `docs/election-mancala-standalone.html` — 기준 구현. 명세와 다르면 이것이 정답.

## 절차
1. 명세와 프로토타입 `<script>`를 읽고 규칙을 스스로 정리한다.
2. `src/engine/` 를 읽고 각 규칙 항목이 어디서 구현되는지 대응시킨다.
3. 특히 의심해서 볼 곳:
   - 다음 정차지 탐색이 출발 권역 자신까지 포함해 6칸을 도는지
   - 포화 권역 건너뛰기, 정차지 없을 때 버스 토큰 소멸(하차 전·후 모두)
   - place 단계: 최소 1개, 최대 2개, 같은 권역 2회 허용, `canPlace` 거짓이면 건너뛰기
   - 셋업 종료 후 플레이어 0으로 돌아가는지
   - 종료 판정이 턴 종료 시점에만 일어나는지, 조건(포화 ≥ 4 또는 예비군 합 0)
   - 동점 처리: 권역은 ⚑(hole[0]), 총점은 남은 예비군
   - 불변성: applyAction이 입력 상태를 변경하지 않는지
4. `npm run test`를 실행해 결과를 확인한다(스크립트가 없으면 생략하고 그렇게 적는다).
5. 필요하면 scratchpad나 임시 스크립트로 구체 상태를 만들어 양쪽 동작을 비교한다. 저장소 파일은 수정하지 않는다.

## 보고 형식
- **불일치**: 규칙 항목 / 기대(프로토타입 근거 행) / 실제(`파일:행`) / 재현 상태
- **누락 테스트**: 테스트로 고정되지 않은 규칙 항목과 제안 테스트 케이스(입력 상태·액션·기대 결과)
- **프로토타입 자체의 의심 동작**: 있으면 별도로. 버그인지 의도인지 단정하지 말 것.
확인하지 못한 항목은 확인하지 못했다고 쓴다.
