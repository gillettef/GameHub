# AstralTab

> v2 (2026-09-22): 게임 규칙을 바둑형 배치 게임으로 재정의했다. 규칙 정본은 `notes/Rules.md`.

---

## 개요

### 한 줄 정의
웹 브라우저에서 친구 2~4명과 즐기는, **바둑처럼 마커를 하나씩 놓아 영토를 넓히는** 카드 기반 우주 전략 보드게임 플랫폼. 손패의 카드로 유닛·건물·마법 마커를 내 시야 안에 놓고, 영토와 마커 점수로 승부를 가린다.

### 제품 목표
- [목표 1] 웹 브라우저에서 친구 초대로 2~4인 방을 만들고 세션을 유지한다. — *근거: 오프라인 보드게임의 디지털 이전을 선호하며 지인 중심의 폐쇄형 플레이를 원한다는 요구 반영.*
- [목표 2] 보드 / 상태 / 진행 세 탭으로 화면을 나누고 스크롤 없이 한 화면에서 대국을 진행한다. — *근거: 보드·손패·비용·시야·점수가 한눈에 들어와야 수읽기에 집중할 수 있다.*
- [목표 3] 비용·시야·전투·점수 계산과 승리 판정을 서버가 자동화한다. — *근거: 수동 계산을 없애 바둑처럼 "어디에 무엇을 놓을지"에만 집중하게 한다.*

### 배경
바둑은 규칙이 단순하지만 돌이 모두 같고 아무 데나 놓을 수 있어 카드 게임의 "무엇을 낼지" 재미가 없다. 카드 전략 게임은 반대로 보드 위 위치 싸움이 약하다. AstralTab은 두 장르를 합친다. 마커마다 비용·시야·점수가 다르고, 시야 안에만 놓을 수 있으며, 놓인 마커는 움직이지 않는다. 지인끼리 설치 없이 링크 하나로 바로 둘 수 있어야 한다.

추정: 바둑의 위치 감각과 카드 게임의 손패 선택이 결합되면 판마다 다른 전개가 나오고, 자동 정산 덕에 한 판이 20~30분 안에 끝나 반복 플레이 동기가 생긴다.

## 문제 및 해결 방안

### 사용자 문제
- **[문제 1]**: 보드·손패·자원·점수를 보려고 화면을 스크롤하거나 창을 오가야 함 → 정보 인지 지연으로 턴당 사고 시간이 늘고 몰입이 깨짐
- **[문제 2]**: 친구와 온라인으로 보드게임을 할 때 동기화 오류나 턴 관리 부재로 흐름이 끊김 → 피로감이 쌓이고 지속 플레이 동기가 저하됨
- **[문제 3]**: 매 판 초기 세팅(맵, 시작 지점, 덱, 초기값)과 규칙 검증을 손으로 해야 함 → 준비에 시간을 낭비하고 규칙 분쟁이 생김

### 해결 방안
- **문제 1**: 보드 탭(격자·시야·영토·손패), 상태 탭(에너지·비용·시야·점수), 진행 탭(로그·패스)으로 나눠 스크롤 없이 한 클릭으로 모든 정보를 본다.
- **문제 2**: 초대 링크 방 만들기와 Socket.io 실시간 동기화, 턴마다 JSON 스냅샷 자동 저장으로 비동기 플레이와 재접속 복구를 지원한다.
- **문제 3**: 맵 선택 → 특수 카드 3장 선택 → 코어 자동 배치 → 초기 에너지·손패 자동 세팅까지 시스템이 처리하고, 배치·전투·점수는 서버 룰 엔진이 판정한다.

### 차별점
- **시야 기반 배치 (바둑 대비)**: 내 마커의 시야 안에만 놓을 수 있어 확장 경로 자체가 전략이 된다. 시야가 겹치는 칸은 누구의 땅도 아니어서 접전 지역이 자연스럽게 생긴다.
- **손패 카드로 마커 선택 (바둑 대비)**: 매 턴 "어디에"뿐 아니라 "무엇을" 놓을지 고른다. 값싼 정찰 드론으로 땅을 넓힐지, 에너지를 모아 요새를 세울지가 갈린다.
- **움직이지 않는 마커와 자동 전투 (카드 RTS 대비)**: 놓인 마커는 그 자리에서 매 턴 사거리 안의 적을 자동으로 때린다. 유닛 조작이 없어 턴이 짧고, 압박은 "어디에 놓느냐"로만 표현된다.
- **설치 없는 웹 기반 2~4인 플레이 (전통 시뮬레이터 대비)**: 링크 하나로 접속해 6개 맵 중 골라 바로 시작한다.

## 타겟 및 시나리오

### 타겟 사용자
- **주요 타겟**: 바둑·체스 같은 추상 전략과 카드 게임을 모두 즐기는 2030 보드게임 마니아 — 지인들과 웹에서 짧고 밀도 높은 수싸움을 원하는 상황
- **2차 타겟**: 우주 SF 테마와 영토 확장 요소를 좋아하며 설치 없는 가벼운 접근을 원하는 층
- **공통 특성**:
  1. 시야·비용·점수처럼 명확한 숫자로 상황을 읽고 최적화하는 플레이를 선호함
  2. 스크롤 없이 한눈에 들어오는 탭 UI로 빠르게 정보를 파악하기 원함

### 핵심 사용 시나리오
**시나리오 1: 친구 초대 2인전, 시야 싸움으로 첫 승리**
1. 사용자가 '방 만들기'로 로비를 열고 초대 링크를 친구에게 보낸다. 맵 '쌍성'을 고른다.
2. 각자 특수 카드 3장(정제소·전함·워프 게이트 등)을 고르고 준비 완료한다.
3. 시작 직후 코어가 양쪽 대칭 위치에 놓이고 손패 4장·에너지 3으로 시작한다. 정찰 드론으로 광맥 쪽 시야를 넓히고 채굴기를 광맥 위에 세운다.
4. ✨ Aha moment: 상대 시야와 내 시야가 겹쳐 경합이 된 중앙에 워프 게이트를 놓아 시야 3을 확보하고, 다음 턴 포격함이 상대 채굴기를 사거리 안에 넣어 자동으로 부순다. 상태 탭의 점수가 뒤집힌다.

**시나리오 2: 4인전, 탈락을 피하고 점수로 역전**
1. '사분면' 맵 4인전. 옆 좌석 플레이어가 전투기 두 대를 내 코어 사거리 안에 놓아 코어 체력이 줄기 시작한다.
2. 상태 탭에서 코어 체력과 상대 손패 장수를 확인하고 차폐막으로 회복, 방어탑으로 반격한다.
3. 반대편 두 플레이어가 서로 소모하는 동안 전초기지로 조용히 영토를 넓힌다.
4. 라운드 제한 도달, 영토 점수 1위로 역전 승리.

### 주요 리스크
- 🔴 **[실시간 동기화·재접속 안정성]**: 세션 끊김 시 진행 불가 → 대응: Socket.io + 턴마다 JSON 스냅샷 자동 저장, 재접속 시 전체 상태 재전송
- 🟡 **[카드·맵 밸런스]**: 특정 특수 카드 조합이나 좌석 순서가 압도적일 수 있음 → 대응: 수치는 `shared/src/data` 한 곳에 두고, AI 자가 대전으로 승률을 수집해 조정. 동점 시 후공 우선 규칙으로 선공 이점 보정
- 🟡 **[3인 맵 비대칭]**: 정사각 격자에 3인을 완전 대칭으로 놓을 수 없음 → 대응: 후공 우선 규칙, 필요 시 좌석별 덤 도입
- 🟢 **[브라우저 렌더링]**: 15×15 보드와 시야·영토 오버레이 렌더 비용 → 대응: 셀 memo, 탭 언마운트 금지

## 속성 설정

### MVP 일정 (추정)
- **1단계**: 룰 엔진 + 탭 UI (핫시트 한 판 완주) — 3주
- **2단계**: 로비·맵 선택·실시간 동기화·저장 복구 — 3주
- **3단계**: AI 대전(2인 Minimax, 3~4인 max-n) + 밸런스 — 3주

### 팀 구성 (MVP 기준)
- 풀스택 개발자: 1명 — 탭 UI, 방 관리, 룰 엔진
- AI/게임 로직 엔지니어: 1명 — 규칙 사본(`rules.py`), 탐색·평가 함수
- UI/UX 디자이너: 1명 — 탭 레이아웃, 우주 테마, 시야·영토 시각화

### 기술 스택
- **백엔드**: Node.js 22 + Express + Socket.io (포트 3101)
- **프론트엔드**: React 18 + Vite + Zustand
- **AI**: Python 3.11 + FastAPI, Minimax / max-n
- **저장소**: 없음 (인메모리 + JSON 파일 스냅샷)
