# AstralTab


---

## 개요

### 한 줄 정의
하드코어 보드게임 마니아가 웹 브라우저를 통해 친구와 텍스트 및 카드 기반의 우주 RTS 전략 대국을 실시간으로 즐길 수 있는 디지털 보드게임 플랫폼

### 제품 목표
- [목표 1] 웹 브라우저 환경에서 친구 초대 기능을 통한 멀티플레이어 방 생성 및 세션 유지 기능을 구현한다. — *근거: 오프라인 보드게임의 디지털 이전을 선호하며 지인 중심의 폐쇄형 플레이를 원한다는 요구사항 반영.*
- [목표 2] 보드, 플레이어 상태, 턴 진행 영역을 탭 기반 UI로 분리하고 화면 스크롤을 최소화한다. — *근거: 복잡한 전략 정보가 한눈에 들어와야 하는 하드코어 보드게임 특성상 가독성과 조작 편의성을 극대화하기 위함.*
- [목표 3] 건물, 유닛, 마법 카드의 자원/마나 생산량 계산 및 승리 조건 판정을 자동화한다. — *근거: 수동 계산으로 인한 플레이 지연을 방지하고 하드코어 전략 게임의 빠른 턴 진행을 보장하기 위함.*

### 배경
디지털 보드게임 시장에서 하드코어 전략 장르는 복잡한 규칙과 세팅 과정으로 인해 오프라인 모임의 물리적 제약을 강하게 받는다. 특히 지인들과 실시간으로 심리전과 자원 관리를 겨루고 싶어 하는 마니아층은 별도의 클라이언트 설치 없이 즉시 접속 가능한 웹 기반의 디지털화 솔루션을 필요로 한다.

추정: 하드코어 보드게임 마니아들은 복잡한 수동 자원 계산보다 전략적 의사결정에 집중하길 원하므로, UI 복잡성을 낮춘 탭 구조와 자동화된 시스템이 도입될 경우 플레이어의 게임 몰입도가 유의미하게 상승할 것이다.

## 문제 및 해결 방안

### 사용자 문제
- **[문제 1]**: 복잡한 하드코어 전략 보드게임을 온라인으로 즐기려 할 때, 플레이어 상태나 자원·마나 생산량, 보드 상황을 파악하기 위해 화면을 과도하게 스크롤하거나 여러 창을 오가야 함 → 정보 인지 지연으로 인해 턴당 사고 시간이 길어지고, 게임의 몰입도가 크게 떨어짐
- **[문제 2]**: 친구들과 함께 온라인으로 보드게임을 진행할 때, 실시간 동기화 오류나 턴 관리의 부재로 인해 게임 흐름이 끊기거나 오프라인 모임 같은 직관적인 상호작용을 느끼기 어려움 → 게임 진행에 불필요한 피로감이 쌓이고 지속적인 플레이 동기가 저하됨
- **[문제 3]**: 매번 게임을 시작할 때마다 복잡한 초기 세팅(특수 카드 선택, 기지 배치 등)을 수동으로 준비하고 규칙을 검증해야 함 → 실제 전략을 구사하고 플레이를 즐기는 시간보다 준비 및 정리에 과도한 시간과 노력을 낭비하게 됨

### 해결 방안
- **문제 1 해결 방안**: 웹 브라우저 기반의 단일 화면 인터페이스 내에서 보드, 플레이어 상태, 턴 진행 상황을 탭(Tab) 구조로 명확히 분리하여, 사용자가 스크롤 없이도 단 한 번의 클릭으로 필요한 모든 전략적 정보를 즉시 파악하고 직관적으로 대처할 수 있게 됩니다. *(하드코어 전략 보드게임 마니아층은 방대한 정보의 빠른 처리와 쾌적한 UI를 중요하게 여기며, 불필요한 마우스 휠 조작을 없애야만 고도의 전략적 사고에만 온전히 몰입할 수 있기 때문입니다.)*
- **문제 2 해결 방안**: 친구 초대를 통한 방 만들기 기능과 실시간/비동기 매치메이킹 서버를 지원하여, 사용자는 물리적 제약 없이 지인들과 원활하게 연결되어 끊김 없는 턴제 대전을 즐길 수 있습니다. *(지인 중심의 폐쇄적이면서도 안정적인 멀티플레이 경험을 선호하는 타겟 성향에 맞춰, 복잡한 공개 매칭보다 확실하고 쾌적한 프라이빗 플레이 환경을 보장하기 때문입니다.)*
- **문제 3 해결 방안**: 덱 구성, 특수 카드 선택, 초기 메인 기지 배치 및 자원/마나 기준표 세팅을 시스템이 자동화하여, 사용자는 복잡한 수동 세팅 과정 없이 곧바로 전략적 유닛 배치와 전투라는 게임의 핵심 재미로 진입할 수 있습니다. *(보드게임의 아날로그적 감성은 살리되, 반복적이고 번거로운 물리적 준비 단계를 제거해야만 플레이어들이 온전히 고차원적인 수싸움과 승리의 성취감에만 집중할 수 있기 때문입니다.)*

### 차별점
- **탭 기반의 올인원 대시보드 구조 (기존 웹 보드게임 플랫폼 대비)**: 기존 툴들은 보드와 플레이어 상태창이 넓게 퍼져 있어 스크롤과 화면 전환이 필수적이지만, 본 제품은 핵심 영역을 탭으로 엄격히 분리하여 하드코어 게이머가 스크롤 없이도 한눈에 전세를 파악할 수 있습니다. *(왜냐하면 정보 탐색에 쓰는 불필요한 인지 부하를 제로(0)로 만들어, 오직 실시간 전략 판단 속도와 깊이에만 집중할 수 있는 환경을 제공하기 때문입니다.)*
- **설치 없는 웹 기반 실시간/비동기 지인 플레이 최적화 (기존 전통 보드게임 시뮬레이터 대비)**: 무거운 클라이언트 설치가 필요한 전통적인 시뮬레이터(Tabletop Simulator 등)와 달리, 웹 브라우저에서 링크 하나로 즉시 접속해 지인들과 동기/비동기 방을 생성하고 플레이할 수 있습니다. *(왜냐하면 복잡한 사전 프로그램 설치나 방화벽 설정의 진입장벽을 없애고, 바쁜 일상 속에서도 지인들과 가장 빠르고 가볍게 하드코어 전략 게임을 즐길 수 있는 환경을 선사하기 때문입니다.)*

## 타겟 및 시나리오

### 타겟 사용자
- **주요 타겟**: 오프라인 보드게임 모임을 즐기며 디지털 환경에서도 깊이 있는 전략 게임을 하고 싶어 하는 2030 하드코어 전략 보드게임 마니아 — 물리적 공간의 제약 없이 지인들과 복잡한 자원 관리와 실시간 턴제 심리전을 웹 환경에서 즉시 즐기고 싶어 하는 상황
- **2차 타겟**: 웹 브라우저 기반의 가벼운 접근성을 선호하면서도 묵직한 SF 세계관과 RTS 요소(영토 확장, 기지 파괴)를 결합한 마니아층 — 복잡한 설치나 클라이언트 다운로드 없이 친구들과 방을 만들어 빠르게 전략 대전을 시작하고 싶어 하는 상황
- **공통 특성**: 
  1. 덱 구성(특수 카드 선택)과 자원/마나 생산 루프를 통한 최적화 플레이(Optimization)를 선호함
  2. 스크롤이나 불필요한 화면 이동 없이, 한눈에 들어오는 직관적인 UI(탭 기반)를 통해 게임 정보를 빠르게 파악하기 원함

### 핵심 사용 시나리오
**시나리오 1: 친구 초대를 통한 실시간 전략 대전 및 첫 승리 경험**
1. 사용자가 웹 브라우저로 접속해 '친구와 함께하는 방 만들기'를 통해 로비를 생성하고 지인을 초대한다.
2. 게임 시작 전, 자신의 전략 성향에 맞는 특수 건물·유닛·마법 카드를 각각 1장씩 선택하여 덱을 구성한다.
3. 탭으로 깔끔하게 구분된 UI(보드/상태/진행)를 통해 스크롤 없이 한눈에 전장을 파악하며, 자원 건물을 먼저 배치해 생산량을 끌어올린다.
4. ✨ Aha moment: 상대방의 기습 공격 타이밍에 맞춰 자원 기준을 극적으로 충족하여 히든 특수 유닛을 즉시 전장에 배치하고, 상대의 메인 기지를 파괴하며 즉시 승리를 거두는 순간

**시나리오 2: 자원 라인 붕괴 위기 극복 및 점수 승리 역전극**
1. 게임 중반, 상대의 공격으로 핵심 자원 생산 건물이 파괴되어 필수 유닛 배치 기준 미달 상태(위기 상황)에 빠진다.
2. 상태 탭을 통해 즉시 줄어든 자원과 마나 생산량을 확인하고, 남은 마법 카드와 영토 확장 전략으로 선회한다.
3. 덱이 모두 소모될 때까지 방어에 집중하며 영토 점수와 건물 점수를 최대화한다.
4. 최종 점수 합산 결과, 아슬아슬하게 점수 승리를 거두며 전략적 대처의 쾌감을 느낀다.

### 주요 리스크
- 🔴 **[실시간 동기화/비동기 매치 서버 안정성]**: 친구와 함께하는 방 만들기 및 멀티플레이 중 네트워크 지연이나 세션 끊김 발생 시 게임 진행 불가능 → 대응: WebSocket 기반의 경량 실시간 통신을 적용하고, 비동기 세션의 경우 상태 자동 저장(Auto-save) 로직을 구현하여 재접속 시 즉시 복구 기능 제공
- 🟡 **[하드코어 유저의 밸런스 피로감]**: 특수 카드(건물/유닛/마법) 조합에 따른 특정 빌드의 압도적 승률(OP) 발견 시 마니아층의 흥미 급격히 저하 → 대응: 초기 오픈 전 사내 테스트(Playtest)를 통해 승률 통계를 수집하고, 출시 후 4주 내에 카드 스펙을 조정할 수 있는 관리자 패치 시스템 사전 구축
- 🟢 **[웹 브라우저 리소스 과부하]**: 격자형 맵과 카드 상태를 탭으로 빈번하게 전환할 때 브라우저 메모리 누수 또는 렌더링 지연 발생 → 대응: Virtual DOM 최적화 및 불필요한 렌더링을 방지하는 컴포넌트 구조 설계 적용

## 속성 설정

### MVP 일정 (추정)
- **1단계**: 코어 게임 루프 및 UI 레이아웃 구현 — 4주 *(이유: 보드게임의 특성상 룰 검증이 먼저이며, 스크롤을 최소화하고 탭으로 영역을 구분하는 UI 구조를 확립해야 하기 때문)*
- **2단계**: 실시간/비동기 방 만들기 및 멀티플레이 기능 개발 — 3주 *(이유: 지인과 함께하는 방 만들기 및 동기식 플레이 환경을 구축하여 핵심 플레이 경험을 검증하기 위함)*
- **3단계**: AI 싱글 플레이 모드 및 최종 테스트 — 3주 *(이유: 혼자서도 게임을 즐길 수 있는 최소한의 AI 대전 상대를 구현하고 버그를 수정하기 위함)*

### 팀 구성 (MVP 기준)
- 풀스택 개발자: 1명 — 웹 브라우저 기반 UI 구현, 실시간 방 만들기 및 게임 로직(자원, 마나, 승리 조건) 구현
- AI/게임 로직 엔지니어: 1명 — 보드게임 규칙 엔진 개발 및 싱글 플레이용 기본 AI 구현
- UI/UX 디자이너: 1명 — 탭 기반의 직관적인 레이아웃 및 우주 배경 테마 디자인

### 기술 스택
- **백엔드**: 추천: Node.js (Express 또는 NestJS) *(비동기/동기 방 관리 및 실시간 상태 동기화에 유리하고 웹 프론트엔드와 언어를 통일할 수 있어 개발 효율이 높기 때문)*
- **프론트엔드**: 추천: React *(컴포넌트 단위 개발과 탭 기반의 복잡한 UI 상태 관리를 효율적으로 처리할 수 있기 때문)*
- **AI/ML**: 추천: Python (Minimax 알고리즘 기반 룰렛 기반 AI) *(복잡한 딥러닝보다는 보드게임의 수읽기에 적합한 전통적인 탐색 알고리즘 구현이 가볍고 빠르기 때문)*
- **인프라**: 추천: AWS (EC2) 또는 Vercel *(소규모 지인 대상 플레이어베이스에서 최소한의 비용으로 웹 서비스를 안정적으로 호스팅하기 때문)*
