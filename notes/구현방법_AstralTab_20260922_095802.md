## WebSocket 기반 실시간 상태 동기화 (난이도: 높음)

**구현 접근**: 서버 측에 Socket.io를 도입하여 클라이언트와 지속적인 양방향 커넥션 라인을 유지합니다. 유닛 이동이나 자원 변동과 같은 게임 상태 변경 이벤트가 발생하면 클라이언트는 액션 페이로드를 서버로 전송하고, 서버는 룰 엔진을 거쳐 갱신된 전체 보드 스테이트를 방(Room)에 참여 중인 모든 소켓 클라이언트에게 브로드캐스트합니다.

**추천 스택/패턴**: Node.js, Socket.io, Redis (세션 및 방 관리용)

**근거**: 실시간 전략(RTS) 보드게임 특성상 0.5초 이내의 지연 없는 상태 동기화가 사용자 경험과 직결됩니다. HTTP 폴링 방식은 불필요한 트래픽을 유발하므로 웹소켓 기반의 실시간 이벤트 푸시 아키텍처가 필수적입니다.

**예상 리스크**: 네트워크 일시 단절 및 재연결 시 상태 불일치(Desync) 발생 가능성 (추정)

## 100ms 이내 탭 전환 반응 속도 구현 (난이도: 보통)

**구현 접근**: React 상태 관리 시 전역 상태(Redux/Zustand)에 모든 탭 데이터를 미리 로드해 두고, 탭 컴포넌트 언마운트 대신 CSS(display: none 또는 visibility)를 활용한 뷰 숨김/표시 방식을 적용합니다. 또한 React.memo와 useMemo를 적극 활용하여 탭 전환 시 불필요한 자식 컴포넌트의 리렌더링을 원천 차단합니다.

**추천 스택/패턴**: React, Zustand, CSS Modules

**근거**: 하드코어 게이머들은 빈번한 정보 탐색을 수행하므로 탭 전환 시 렌더링 지연이 발생하면 몰입도가 급격히 저하됩니다. DOM을 매번 파괴하고 생성하는 방식보다 인메모리 상태 유지 및 마운트 최적화가 성능 확보에 가장 유리합니다.

**예상 리스크**: 대규모 격자 맵 컴포넌트가 숨겨진 상태에서 DOM 노드가 과도하게 누적될 경우 메모리 사용량 증가 (추정)

## 전투 교전 및 피해 자동 판정 (난이도: 높음)

**구현 접근**: 서버 측 게임 루프 내에 순수 함수 기반의 전투 판정 모듈을 구현합니다. 유닛이 동일 셀에 도달하면 양측의 스펙(공격력, 방어력, 체력)을 객체 형태로 가져와 공식에 대입하여 즉시 데미지를 산출하고, 결과 데이터(체력 감소, 유닛 사망 여부)를 이벤트 로그와 함께 상태 객체에 반영한 뒤 클라이언트로 즉시 송신합니다.

**추천 스택/패턴**: Node.js, 순수 JavaScript 룰 엔진 모듈

**근거**: 자동화된 전투와 빠른 턴 진행은 본 제품의 핵심 가치이므로, 클라이언트 측 위젯이 아닌 권한이 통제된 서버 측에서 전투 연산을 단일 진실 공급원(Single Source of Truth)으로 처리하여 치트 및 데이터 위변조를 방지해야 합니다.

**예상 리스크**: 복수 유닛 동시 교전 시 데미지 정산 순서 오류로 인한 예외 케이스 발생 가능성 (추정)
