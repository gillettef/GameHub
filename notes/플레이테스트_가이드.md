# 플레이테스트 가이드

카드 콘텐츠 5종(수업/마법생물/연구/탐험/마도서)이 모두 초안 상태이므로, 실제로 여럿이 플레이해 보며 수치를 조정하는 단계입니다. 이 문서는 **준비 → 진행 → 기록 → 조정** 순서로 정리했습니다.

## 1. 실행 방법

### 1-1. 서버 켜기 (내 PC 한 대에서)

```bash
cd server
npm install          # 처음 한 번만 (client도 cd client && npm install)
npm run playtest     # 클라이언트를 빌드하고 서버를 실행
```

서버가 뜨면 아래처럼 접속 주소가 출력됩니다.

```
서버가 http://localhost:8080 에서 실행 중입니다.
  스마트폰 접속 주소: http://192.168.x.x:8080
```

- 참가자는 **같은 와이파이**에서 스마트폰 브라우저로 `스마트폰 접속 주소`를 엽니다.
- 접속이 안 되면 Windows 방화벽이 8080 포트를 막고 있을 수 있습니다 (공용 네트워크로 잡혀 있는지 확인, Node.js 허용).
- 화면을 고치면서 테스트하려면 서버(`npm run dev`)와 클라이언트(`cd client && npm run dev`, 주소 `http://<PC IP>:5173`)를 따로 띄웁니다. 클라이언트 dev 서버를 외부에 열려면 `npm run dev -- --host`.
- 외부(다른 네트워크) 사람과 하려면 AWS 배포가 필요합니다 (`AGENTS.md` 기술 스택 참고).

### 1-2. 진행 순서

0. 사람이 모자라면 방장이 대기실에서 **🤖 봇 친구 추가하기**로 봇을 채울 수 있습니다 (혼자 봇 1~4명과도 가능)
1. 한 명이 방을 만들고 방 코드를 공유 → 나머지가 코드로 입장 (2~5인)
2. 방장이 게임 시작 → 12개월(라운드) 진행, 6개월 후 중간고사, 12개월 후 기말고사
3. 1개월 = 2주차 정규수업(카드 선택) → 3주차 자율활동(매력이 높은 순서로 구역 선택, 남은 체력토큰으로 집중, 주문 대결은 아직 안 고른 한 명을 강제 지목, 연구실은 지력만큼 연구 카드를 펼쳐 1장 선택) → 자동 정리, 6·12개월 끝에는 시험
4. 화면 하단의 **📜 최근 소식**에서 탐험/대결/조련 결과를 확인할 수 있습니다

### 1-3. 알려진 제약 (테스트 중 이상해도 버그가 아닙니다)

- 서버 프로세스 메모리에만 상태를 보관합니다. **서버를 재시작하거나 브라우저를 새로고침하면 진행 중인 게임을 이어할 수 없습니다** (재접속 미지원, 기획상 의도).
- 카드 일러스트가 없습니다 (마법생물은 속성 이모지로 대체).
- 게임 시작 전 초기 능력치는 전원 1입니다 (임시안).

## 2. 플레이 전 자동 점검 (개발자용)

```bash
cd server
npm run smoke -- 4 8080     # 서버가 떠 있는 상태에서, 가짜 플레이어 4명이 WebSocket으로 한 판을 끝까지 진행
npm run smoke:bot -- 3 8080 # 사람 1 + 봇 3 한 판 완주와, 게임 중 이탈한 사람을 봇이 이어받는지 확인
npm run simulate -- 1000 4  # 봇 시뮬레이션으로 밸런스 통계 출력 (서버 없이 실행)
npm run check               # 규칙 단위 검증 (구역 2인 제한·추가 비용, 매력 이전, 협력 탐험, 시험 주사위 등, 서버 없이 실행)
```

- `smoke`: 프로토콜/엔진이 끝까지 정상 동작하는지, 비공개 정보(덱, 다른 사람의 수업카드)가 새지 않는지 확인합니다.
- `check`: 핵심 규칙이 기획대로 동작하는지 엔진을 직접 호출해 확인합니다. 규칙을 바꾼 뒤에는 먼저 이걸 돌립니다.
- `simulate`: 전략별 승률, 최종 능력치 분포, 활동 선택 비율, 일반 수업카드 소진율/소진 라운드를 출력합니다. 봇은 단순해서 절대값보다 **상대적 차이**만 참고합니다.

### 시뮬레이션에서 이미 보이는 신호 (2026-09-30 규칙 개편 후, 4인, 150판 기준, 사람 플레이로 검증 필요)

| 관찰 | 해석 |
|---|---|
| 연구실 몰빵 승률 약 48% (기대 25%) | 구역 2인 참여로 연구실을 매달 확보할 수 있어 영구 능력치 이점이 더 커짐. 연구 카드 수치 축소나 연구실 두 번째 참가 비용 상향 검토 |
| 토너먼트 몰빵 약 9%, 주문 대결 몰빵 약 14%, 탐험 몰빵 약 6% | 한 활동만 고집하면 손해 — 의도한 방향. 주문 대결은 매력 참가비 때문에 더 불리해짐 |
| 일반 수업카드 소진: 2인 약 10R, 3인 약 8.8R, 4인 약 7.5R, 5인 약 6.8R | 등급별 비용(일반 1/1, 특별 2/2)만으로는 소진이 늦춰지지 않음. 일반 카드 습득 비용을 체력토큰 2개로 올리면 소진이 거의 사라지지만 초반(1~2R)에는 아무도 카드를 습득할 수 없음 |
| 인원이 적을수록 능력치가 크게 오름 (2인 평균 10, 5인 평균 5~6) | 덱이 인원 수와 무관하게 같아 2인 게임이 과열됨. 덱 크기 조정은 테스트 후 결정 |
| 인원별 평균 성취도: 2인 약 85, 5인 약 32 | 인원별 규칙 보정이 필요할지 실제 플레이로 확인 |

## 3. 관찰할 것 (플레이 중 메모)

**재미/템포**
- [ ] 한 판이 몇 분 걸렸는가 (목표: 인당 약 15분, 4인 60분 내외)
- [ ] 기다리는 시간이 길지 않았는가 (특히 3주차 순서 대기)
- [ ] 12개월이 길게 느껴진 시점이 있는가 (몇 개월째부터?)

**밸런스**
- [ ] 초반(1~3개월)에 할 게 너무 적거나 체력토큰이 부족하지 않았는가
- [ ] 한 명이 일찍부터 크게 앞서 나갔는가 (앞선 원인: 카드/운/전략?)
- [ ] 항상 고르게 되는 활동, 아무도 고르지 않는 활동이 있는가
- [ ] 중간고사/기말고사 결과가 운(주사위)에 너무 좌우되는가
- [ ] 학점 지급(3/2/1)이 성취도 차이를 만들기에 충분한가
- [ ] 마법생물이 값어치를 하는가 (주문서를 쓸 만한가), 특정 카드가 너무 강/약한가
- [ ] 주문 대결이 견제 수단이 되는가, 아니면 그냥 마도서 뽑기인가

**이해도/UX (모바일)**
- [ ] 규칙 설명 없이 화면만으로 다음 행동을 알 수 있었는가
- [ ] 카드 설명(능력 텍스트)이 이해되는가
- [ ] 화면이 길어서 스크롤이 힘들지 않았는가, 터치가 어렵지 않았는가
- [ ] "왜 이런 결과가 나왔는지"를 알 수 없는 순간이 있었는가

## 5. 조정 지점 (어디를 고치면 되는가)

## 6. 테스트 순서 제안

1. **2~3인 짧은 테스트**: 화면/조작 문제와 규칙 이해도를 먼저 잡는다 (규칙 위주, 밸런스는 보지 않음)
2. **4인 본 테스트 2판 이상**: 밸런스와 시간 확인. 판마다 수치는 바꾸지 말고 기록만 한다
3. 기록을 모아 조정 후보를 정하고, 시뮬레이션으로 검증한 뒤 수치를 바꿔 재테스트한다
